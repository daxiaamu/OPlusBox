# OPLUSBox AirDrop components

Current component revision: 4. ROOT module version: 0.6. This directory contains binary assets, an authenticated catalog and documentation only.

The app checks the actual Wonder vendor interfaces rather than requiring an exact firmware build string or WLAN module digest. Supported ColorOS major version, Android 16 or newer, ARM64, matching GMS/Mosey adapters, security types and early-registration support remain required. Missing-component installation currently uses KSU/SukiSU initrc; Magisk/APatch installation is not implemented. A complete compatible stock backend can be reused.

The package contains six official files: Mosey APK, native server, FFI library and three declarations. It contains no kernel, WLAN module or system-directory snapshot. Additive native overlays retain current system declarations. Revision 4 reuses the verified revision 2 backing because the official bytes are identical, avoiding another nine MiB in the small metadata partition. The app checks for a minimum free-space reserve before installation.

The integrated ColorOS adjustment removes only the standalone `cn.google.services` declaration from `/my_product/etc/permissions/oplus_google_cn_gms_features.xml`. Each boot reads the current original system file and preserves all other lines, including `com.google.android.feature.services_updater` and new OTA declarations. No other manufacturer settings are included. Unrecognized XML is rejected without masking the original. The script uses one file bind at post-fs-data and does not remount a partition. It does not force-enable a tile or modify its layout. The app checks the actual PackageManager feature state before enabling AirDrop.
